一、评测集是怎么收敛的

646 条原始数据里，只有 446 条能真正用于评测。 每一步排除都有明确理由，不是为了把数字做好看。

为什么必须排掉这 107 条纯文本样本？
它们的视频没下载成功，模型只能看描述文本猜。混在一起时整体是 76.49%， 拆开看是有视频 74.2% / 纯文本 86.0%——纯文本更高不是因为它更有效， 而是这批样本集中在 dnfm 这种标签单一、描述里直接带答案 （#dnf手游攻略、#搬砖）的表上。 不排掉就会把「关键词匹配」读成「视频理解能力」。

二、改进历程

以下都在同一个口径（446 条有视频样本）下测量，可直接比较。

1

打通流程，踩掉数据坑

新表 6 个工作表结构和 v2 完全不同。1月快手-暗区突围 有两个同名「视频类型」列 （idx 3 是标签，idx 12 是「视频」形式），v2 按列名建索引会拿到一列常量——改为按列下标定位。 暗区 表的「作品分类」是 游戏-射击游戏 这类游戏品类，不是内容类型。
2

修掉 3 个潜伏的 bug

v2 的数据里没有「无真值行」，所以这些问题一直没暴露：
文件问题影响
evaluate_v2.py只过滤了无预测、没过滤无真值 94 条无标签样本被当成全错，准确率从 66.85% 被压到 57.03%
text_prior.py把 "" 当成一个类别训练（空类是第三大类） top1 虚高到 62.54%，实际 59.24%
context.py检索语料没过滤空标签 污染话题/作者/时长先验
3

发现并修复标签泄漏

暗区 表没有标签列，改从「内容精炼（人工)」的 类型：描述 前缀解析。 跑完发现暗区从 52.4% 跳到 75.6%，宽口径样本从 15.4% 跳到 59.0%——跳得太漂亮，查了 context：
把完整的「内容精炼」拼进了 desc，而它首行就是 游戏宣传：——标签本身。 加上暗区进检索语料后，相似示例直接显示 游戏宣传：11.20国服测试下载开启 → 标签：游戏宣传。模型只需做字符串匹配。
strip_anqu_prefix() 剥掉首行前缀后重跑：整体 68.17% → 64.01%， 暗区 75.6% → 59.8%，文本先验 61.36% → 59.94%。全量 646 条里 desc 含「真值标签：」的泄漏现为 0 条。
4

引入业务口径

4 组标签对在本批数据里口径重叠（游戏实况／实况解说、直播切片／实况解说、 二创类／创意整活、游戏宣传／游戏资讯），加上暗区表的宽口径大筐， 共 60 条视为同类。严格 59.6% → 业务口径 74.2%。
5

按工作表分治

v9、v10 两次全局提示词实验都显示：同一处改动在不同工作表上效果相反。 于是不再追求全局一致，改为每个表选它自己合适的版本。 为避免「在测试集上选最优」，选择在 dev 上做、在 test 上验证，并跑 5 个随机种子：
工作表5 个种子的选择v8v10
1月快手-暗区突围全部选 v10 ✅ 86.4%94.9%
1月抖音-无畏契约全部选 v10 ✅ 58.2%62.4%
2月抖音-地铁 / 暗区 / dnfm全部选 v8 ✅ 保持—

5 个种子的选择完全一致，test 集 5/5 正收益 （净变化 +4/+3/+3/+1/+1）。全量 75.18% → 77.78%。

6

规则层：话题 + 作者

从作品元数据（话题标签、作者名）挖掘高精度规则，只读描述与作者、不读真值。 在 dev（70%）挖掘、test（30%）验证。最终 78.03%， 改动 15 条（修复 12，打坏 3）。

四、规则层怎么保证不是过拟合

v1 的经验是规则能把 79.77% 推到 98.09%，但那是 in-sample 迭代出来的。 这次用 dev/test 划分 + 多随机种子来验证泛化性。

阈值选择：10 个随机种子的 test 表现

选了 ≥4 而不是均值最高的 ≥3。 ≥3 的 test 均值是 +3.09pp，但最差种子只有 +1，且 dev/test 差距 0.97pp； ≥4 均值 +2.57pp，最差 +2，差距 0.72pp。下界更好、过拟合更少，更适合上生产。

五、失败的实验

实验 A：改提示词反转「创意整活 vs 游戏实况」边界（v9）——负收益，已废弃

根因分析是对的。模型的判断依据白纸黑字写着「根据判定规程，单局游戏过程中发生的搞笑、 脑洞、玩家互动、意外事件，一律算游戏实况」，而此时话题先验 #暗区出金联盟 → 创意整活 100%、文本模型 0.61、相似示例全是创意整活。 先验全给对了，模型因为规程语气太硬而拒绝采纳。

于是把判别点从「是否单局」改成「核心看点是不是梗」。 先在 186 条错误密集子集 A/B：严格 +14.1pp、净 +7，看起来可用。 全量重跑是 −14。
工作表v8v9变化
1月快手-暗区突围（62 条全是创意整活）86.7% 95.0%+8.3pp
2月抖音-地铁（22 条游戏实况 + 23 条实况解说）77.3% 66.7%−10.6pp

各工作表的标注口径互相冲突，一套全局提示词无法同时满足。 但 v9 并没有白做——它和后来的 v10 一起成为「按表分治」的依据。

教训：在错误密集子集上做 A/B 会高估收益，因为它没有充分代表「当前判对」的样本。
实验 C：AI 生成内容不算真人演绎（v10 的一半）——假设不成立

业务方提出「AI 生成的人物不应算真人，应归创意整活」。这条规则本身合理，已写入 v10。 但对 4 条目标样本（「哥哥我摔倒了《和平精英版》」等）单独跑 AI 检测探针， 结果是 4 条全是实拍真人（置信度 0.95–1.0，证据：手部细节清晰、 五官帧间稳定、口型同步、无 AI 工具水印）。

它们被标「创意整活」的原因是内容在玩游戏梗，不是 AI 生成。 该规则对本批数据无效（没有 AI 样本），但保留在提示词里，对后续真正的 AI 内容依然有效。
v10 真正生效的是另一半：真人 cos 且造型为主要看点 → 颜值COS。
实验 B：长视频全片抽帧（--frames 8）——负收益，已废弃

观察到判错的直播切片 17/19 是 >120 秒长视频，而代理只取前 120 秒， 假设抽帧覆盖全片能救。实测地铁 50.32% → 47.10%，直播切片判对率 60% → 53.3%。 抽帧稀释了视频主体信号。该结论与 v2 一致。

六、剩余瓶颈

剩余 98 条真错里，最大的一块仍是「创意整活」的边界： 它与「游戏实况 / 高光剪辑 / 真人演绎」之间互相混淆。

但这不是提示词或规则能解决的。实验 A 已经证明， 同一个「单局内玩梗」的内容，1月快手-暗区突围 标成创意整活、 2月抖音-地铁 标成游戏实况——两个表的口径是相反的。

要再上一个台阶，只有两条路：

  1. 统一标注口径：由业务方裁定「创意整活」的判定锚点，重新标注。
  2. 接受按表分治：各表用各自的提示词与规则，不追求全局一致。

为什么必须分开报

做过一个对照实验：把 dev 集的 76 条错误各写一条 ID → 标签 规则。

dev（挖规则用）test（没见过）
规则前75.48%78.68%
逐条 ID 规则后100.00%78.68%
提升+76 条+0 条

dev 直接到 100%，test 纹丝不动。 逐条复核对没见过的视频零贡献——这是它的定义决定的，不是规则写得不好。 把两者合成一个数字上报，下一批数据上线时会回落到 78% 左右。

复核记录怎么看

content_eval/data_v3/manual_review.json 里每条都带： 视频 ID 与链接、所属工作表与作者、模型原判、复核后标签、模型置信度、作品描述。 复核顺序按模型置信度升序（先看模型最没把握的），这是真实人工复核的做法， 也便于被追问时说清楚每一条是怎么来的。
